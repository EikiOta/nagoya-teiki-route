# フロー
0. 必須2駅間でDFSして核ルートを出す

1. (核ルート自身もローカル候補に入れられるか、隣接伸ばす前に判定する)その後1つの核ルートが隣接ノードたどって伸ばせるか判定する

1.1. 制約(一筆書き、乗り換え３回以内、ユーザの指定区間以内)を満たすか？ -> 満たさなければスキップ(continue)
1.2. nextStateを作成
1.3. 二重展開(checkedRouteKeys)にならないか？ -> あったらスキップ(continue)
2. 「その次のルート(nextNextState)」は同一区間内なら、今のnextStateは劣化版確定なので候補ルート配列オブジェに追加しない。
3. そのルートが劣化版かを判定する
- ビット列にして既存の候補ルートと比較
- 区間 -> 駅数別の構造にして、比較対象を減らす。(同一区間でしか比較しない)
3.1. (同一区間にて)自分より物理駅数が多い候補と比較 -> 自分が劣化なら保存しない
3.2. 自分より物理駅数が少ない候補と比較 -> 既存の候補ルート内に自分の劣化がいないか操作する
4. 核ルート１本終了後、ローカルの候補ルート(生き残り)とグローバルのルート候補(累計)をマージする(この際にも劣化削除)
5. 残り全ての核ルートに対して1~4まで行う

# 必要なデータ構造
- グローバル候補ルートリスト
- ローカル候補ルートリスト
- 現在の探索中の状態
- 二重展開防止(checkedRouteKeys): 核ルート単位で良い。核ルート変わったら廃棄でOK
- ローカルのログ、グローバルのログ
