# 概要 
- 名古屋市営地下鉄は「路線図内で一筆書き」「乗り換え３回まで」「経路・接続号線を判別する駅（大曽根、金山、西高蔵、国際センター、吹上）の総数が5駅を超えない」の３条件を満たしていればどのようなルートでも作成できる。
    - 【重要】定期券の駅のスタートとゴールもどこでもよい。
        - たとえば本山(家) -> 名古屋(職場)だとしても定期のスタート・ゴールは藤が丘～高畑にしてOK。
    - 選択した定期区間ルートに入っている駅であれば、乗車降車は定期扱いなのでタダになる。 -> プライベートでもよくいく繁華街なども入れたい傾向あり。先の例だと藤が丘～高畑で東山線1本にするのではなく、藤が丘～本山（名城線）～栄～名古屋と敢えて迂回してカバーする駅数を稼ぐという駆け引きがある。
- そこで、ユーザの定期種別（大人、学生、障碍者など）、必ず通りたい駅２駅(必須駅)を選択して最適ルートを出力する。

## 定期券の仕様 
- 必ず定期券のルートに沿って乗る必要はない。
- 乗り降りする駅（改札を通過する駅）が定期券内に入っていればOK。ルートはどうでもよい。
- 通過駅が定期券内に入っている必要はない。

# 用語 
- 必須駅: ユーザが必ず通る駅。2つ選択する。自宅と職場・学校、など。
- 優先駅: ユーザができれば定期区間内にカバーしておきたい駅。
- それ以外の駅: 特に定期内にあってもなくてもどっちでもよい扱い。
- 総駅数: その定期ルートで乗り降りできる駅の数（一筆書きのため重複なし）
- 最短経路: 駅数ではなく、駅間距離(distance)の合計が最も少ない経路のことを指す。
    - 区間は総距離で決まるため。

# 機能一覧 
★はMVP(初期リリース)で実装

## 1. ★定期券の条件(大人、学生、障碍者など)を指定する機能 

## 2. ★必ず通る(必須)駅を２駅指定する機能 
- **必須駅を2駅登録した段階で、その2駅を結ぶ最短経路を探索し、出力する**

## 3. ★許容できる定期区間を指定する機能(3区以内など)(値段も表示する) 
- 上記の必須駅を変更すると、自動で最短経路の区間に設定される。
    - 最短経路の区間よりも小さくすることはできない。

## 4. ★できれば定期内にカバーしたい駅(優先駅)を指定する機能 
- 登録した順番に優先度が高くなる
- D＆Dなどでシャッフル可能
- 任意入力

## 5. 路線図から上記の必須駅・優先駅を選択できる機能 

## 6. ★入力した条件で探索して定期券候補ルートを一覧表示する機能 
- デフォルトは「定期代が安い順（区間が低い順）」でソート
- yahoo乗り換えルートの表示のイメージ
- 候補ルート一覧では「区間(料金)」「乗り換え回数」「大雑把なルート(乗り換えがある場合は明記する)(名古屋~伏見~塩釜口 といった感じ)」「ルート内に含まれている優先駅」「ルート内に含まれていない優先駅」「総駅数」
- 「大雑把なルート」で展開したら具体的に通る駅が一覧で表示されるようになる。

## 7. 出力結果から選択したルート候補を、路線図に表示する機能 
- 出力結果から任意のルートを選択すると、路線図に線が引かれる

## 8. ★出力された「定期券ルート候補」をソートする機能 
- 「定期代が安い順（つまり区間が低い順）」「できれば通りたい駅(優先駅)をカバーしている順」「総駅数が多い順」にソート可能。
    - 優先駅に優劣をつけるのは、「優先駅P1を含んでいるルート」は「優先駅P3だけ含んでいるルート」より高く評価 「P1＋P2を含む」ルートは、「P1だけ」のルートよりさらに高く評価、といった感じで単純な辞書式。

### 定期代が安い順（つまり区間が小さい順）
ソートの優先度は、定期券安さ(区間の小ささ) -> 優先駅の多さ(辞書式) -> 総駅数が多い

### できれば通りたい駅(優先駅)をカバーしている順 
ソートの優先度は、優先駅の多さ(辞書式) -> 定期券安さ(区間の小ささ) -> 総駅数が多い

### 総駅数が多い順 
ソートの優先度は、総駅数が多い -> 優先駅の多さ(辞書式) -> 定期券の安さ(区間の小ささ)
